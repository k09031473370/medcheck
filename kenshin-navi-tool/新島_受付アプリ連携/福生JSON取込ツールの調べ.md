# 福生の受付アプリ JSON → 健診ナビ 取込ツールの調べ（新島で使うために）

作成 2026/11/07。読んだだけ。ツール・設定・健診ナビには何も書いていない。

## 1. ツールと設定ファイル

| ファイル | 役目 | 健診ナビへ |
|---|---|---|
| `受付結果取込.ps1` / `.bat` | 健診ナビに**もう予約がある人**の差分を書く（受付番号・カナ・生年月日。`-WithCourse` でコース） | 書く（プレビュー → Y） |
| `予約取込Excel作成.ps1` / `.bat` | 健診ナビに**まだ予約がない人**の「予約データ取込」用 Excel（33 列）を作る | 読むだけ（Excel を健診ナビの画面で取り込む） |
| `福生取込.ps1` / `.bat`・`福生取込GUI.ps1` | 上の 2 本を順に呼ぶ（事前チェック → 受付番号 → Excel → 健診ナビで取込 → もう一度受付番号） | 中身は上の 2 本 |
| `form/fussa_company_map.csv` | 振り分け表の事業所名 → 健診ナビの団体CD | |
| `form/fussa_option_map.csv` | オプション記号 → 健診ナビのコード・名称 | |
| `form/yoyaku_import_app.txt` | 健診ナビの予約データ取込の exe の場所（自動で開く用） | |
| `backup/受付結果取込_前回.txt` | 前回取り込んだ JSON の series_id・exported_at・revision | |
| `backup/対応表_<series_id>.csv` | 受診者ID ↔ PK_SEQ ↔ 個人ID の控え（毎回上書き） | |

`form/yoyaku_settings.csv`・`yoyaku_course.csv`・`yoyaku_dantai.csv` は別の取込（東京実業の当日フォーム）用で、福生の流れでは使っていない。

## 2. 福生のための決め打ち（新島で使うなら変える所）

| 決め打ち | 場所 |
|---|---|
| 団体名に「福生」（`-DantaiLike` の既定） | 受付結果取込・予約取込Excel作成・福生取込 |
| コース A/B/C → FA/FB/FC（名称 福生A/B/C） | 受付結果取込（84 行）・予約取込Excel作成（80 行）・福生取込（113 行）の 3 か所 |
| 対応表 `fussa_company_map.csv` / `fussa_option_map.csv` | 3 本とも（受付結果取込は事業所の対応表を読むだけ） |
| 前回の印 `受付結果取込_前回.txt`（**1 つだけ**） | 受付結果取込 |
| 画面・見出しの「福生」 | 福生取込・福生取込GUI |

**福生のファイルは変えず、新島用は別のファイル（別名の ps1・`niijima_*` の対応表・別の前回の印）にする。**

## 3. 案件識別子（series_id）

- JSON の `series_id`（福生は `fussa_2026`）を、ツールは次に使っている
  - 古いファイルの取込防止（前回の印と series_id が同じときだけ比べる）
  - 同時に 2 人が流さないためのロック名（`RECEPTION_IMPORT:<series_id>`）
  - 対応表のファイル名（`対応表_<series_id>.csv`）
- 新島は **`niijima_2026`**（会期で分けるなら `niijima_2026_11`）。新島の受付アプリの出力にこの値を入れる
- ★注意: 前回の印は **1 ファイルだけ**。福生と新島を交互に流すと、前回の印が別の案件で上書きされ、古いファイルの取込防止が効かなくなる → 新島用は `受付結果取込_前回_niijima_2026.txt` のように案件ごとに分ける

## 4. コース

- 福生: 受付アプリは A/B/C、健診ナビは FA/FB/FC（団体ごとにコースがあるかを福生取込の事前チェックで確かめる）
- 新島: 健診ナビから事前登録するので、**受付アプリに健診ナビのコースコードをそのまま持たせる**のが安全（読み替え表が要らない）
- 受付アプリで記号を使うなら `niijima_course_map.csv`（記号 → コースコード・名称）を作り、新島の団体ごとに `T_COURSE1` にそのコースがあるかを事前チェックで確かめる
- 新島の実際のコースは `新島受診者一覧.bat` の Excel（コースコード・コース名の列）で分かる

## 5. 血液検査オプション

福生の記号（`fussa_option_map.csv`）:

|---|---|---|
| F | OPJ017 男性用セット（PSA・BNP） | 血液 |
| G | OPJ018 女性用セット（CA15-3・CA125・BNP） | 血液 |
| H | OPJ019 消化器系がんセット（CEA・CA19-9・AFP） | 血液 |
| I | OPJ004 ABC健診 | 血液 |
| J | OPJ009 脳梗塞リスクマーカー | 血液 |
| K | OP0008 アレルギー39種類セット | 血液 |
| D・E・L・M・N | 乳腺超音波・腹部超音波・子宮細胞診・便潜血2日法・じん肺 | — |
| O | 溶接ヒューム（健診ナビにコード無し。取り込まない） | — |

| | 事前登録（既存予約）から | 受付で追加 |
|---|---|---|
| 中身 | 健診ナビの予約の料金明細 `T_RYOUKIN` の `OP〜`（`新島受診者一覧.bat` のオプション列） | 受付アプリの `actual.options`（追加・中止は `derived.options_added / removed`） |
| ツールの扱い | 予約にもう入っている | **既存の予約には書かない。** 「★オプション変更 → 健診ナビの画面で対応」と一覧に出すだけ（料金行・検査行を作るのは健診ナビの画面の仕事） |
| 予約が無い人 | — | 予約取込 Excel の「オプション検査1〜10」に健診ナビのコードを書く（健診ナビが行を作る） |

新島で用意するもの: `niijima_option_map.csv`（記号・健診ナビのコード・名称・**採血の有無**）。当日追加の血液オプションは検体依頼の前に健診ナビの画面で付ける必要があるので、一覧で目立たせる。

## 6. 同じ JSON を毎日取り込んだとき（受付アプリの JSON は名簿全員の累積）

| 場面 | 今のツールの動き |
|---|---|
| 同じファイルをもう一度 | 「前回と同じファイル」と出て、差分 0 件 |
| 前回より古いファイル | 止まる（`-Force` で続行できる） |
| 受付番号が既に同じ | 何もしない（毎日流しても二重に書かない） |
| 受付番号が健診ナビと**違う**（アプリで直したなど） | **上書きする**（プレビューに 旧 → 新 で出る） |
| 受付アプリで受付番号を消した | 健診ナビの番号は消さない（そのまま残る） |
| 予定日と違う日に受付 | 健診ナビの予約の受診日と受付日が違えば**書かない**。健診ナビで受診日を直してから流し直す |
| カナ・生年月日 | 健診ナビが空のときだけ書く。違う値は書かずに知らせる |
| 受付アプリで取消 | 健診ナビの予約は**取り消さない**（知らせるだけ）。予約取込 Excel にも出さない |
| オプション・採血/胃/尿の変更・便の本数 | 書かない（知らせるだけ） |
| お知らせ | 状態を覚えないので、前日までに対応済みの取消・オプション変更も毎回出る |
| 予約取込 Excel | 健診ナビに同じ氏名の予約が（JSON の日付の範囲に）あれば出さないので、二重登録しない。`-Ymd` でその日に受付した人だけにできる |
| 照合 | 毎回、漢字氏名（空白を詰め、旧字を新字に揃えたもの）で 1 件だけ一致した予約。対応表は残すが照合には使っていない |

## 7. 新島で変えた方がよいこと（案。まだ作っていない）

1. **予約ID（PK_SEQ）で当てる。** JSON に `navi.reservation_id` を持たせ、氏名照合は確かめ（個人ID・氏名が事前登録と同じか）だけに使う
2. 前回の印・対応表・ロックを `series_id` ごとに分ける（福生と混ざらない）
3. 健診ナビに**別の受付番号が入っていたら上書きしない**で知らせる（福生は上書きする）
4. お知らせは「前回の取込から変わったもの」だけにする（毎日同じ取消・オプションが出ない）
5. 当日追加の**血液**オプションを、お知らせの先頭に分けて出す
