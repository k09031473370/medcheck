## 1. 何をするものか

健診の結果が入ったExcelを読んで、**健診ナビのDBに直接書き込む**ツール。手入力の置き換え。

健診ナビ本体には手を入れない。外部のPowerShellスクリプト群として `C:\Users\User\Documents\excel_tools` に置いてある。

### なぜDBに直接書くのか

健診ナビの「検体検査結果取込」を使おうとしたが、`列 'I' が無効です` で落ちた。
`UPDATE T_KENSA SET KEKKA=... WHERE PK_SEQ=... AND KOMOKU_CD=...` が実機で確実に動くことを確認したので、そちらを採用した。

## 4. 作業フロー（リアンの場合）

```
① 受診者取込   ツール「予約取込ファイルを作成」→ 健診ナビ「予約データ取込」で登録
①-b 受付番号   ツール「受付番号を設定」（氏名照合でUKE_NO_KENSAを書く）
② 結果取込     ツール「3.プレビュー」→「4.書込実行」
③ 血液取込     ツール（SRLのExcel）+「名簿でしぼり込む」
④ 自動判定     健診ナビ（BMI・標準体重・判定はここで計算される）
```

**①-b が必要な理由**: 予約取込フォーマットに受付番号の列が無い。予約登録では番号が入らないので、後から氏名照合で入れる。

**④は必ず最後**。血液を入れる前に判定を回すと血液抜きの判定になる。

芝浦巡回AIデータは氏名も受診日も無いので②のみ。受付番号が未設定なら `受付番号リスト_ひな形.xlsx` に氏名+番号を書いて「受付番号を設定」を使う。

## 5. データレイアウト

### 5-1. リアンパターン（106列・見出しあり）

主な列: 2=受付番号 / 3=受診日 / 7=氏名 / 8=フリガナ / 17-20=身長体重体脂肪腹囲 / 23-26=視力 / 27-30=血圧 / 32-34=尿 / 38-41=聴力 / 42=胸部X線フィルムNo / 46=空腹 / 50=診察判定 / 51-54=他覚所見 / 55-56=生理妊娠 / 57-59=自覚症状 / 60-71=既往歴家族歴（**取込不可**） / 72-93=問診Q1-22 / 95-100=胸部X線 / 101-105=心電図 / 106=コース

- 問診13/16/22 は `084013/084016/084022` ではなく **`H30-0061` / `H30-0062` / `R06-0004`**
- 既往歴(60-65)・家族歴(66-71)は T_KENSA に枠が無く取り込めない（健診ナビでは別テーブル管理）
- 自覚症状は `code_map.csv` でフォームのコード(010〜260)を健診ナビの結果CDへ変換。**9種が未割当**（020鼻づまり/050視力低下/110動悸息切れ/130むくみ/150胃腹痛/160下痢便秘/190かゆみ/200発疹/260物忘れ）

### 5-2. 芝浦巡回AIデータ（46列・見出しあり）— 2026/08/02 実データで確定

`受付NO / Q1-22 / 食事時間 / 身長 / 体重 / 腹囲 / 血圧×4 / 視力(種別+値)×2 / 聴力×4 / 聴力備考 / 尿×3 / 診察 / 胸部レントゲン / 心電図`

**氏名も受診日も無い。**

実データ `0615_0617.xlsx`（48人）で分かったこと:
- **46列だった**。旧対応表は44列想定で「視力備考」列があると思っていたが実際には無く、
  36列目から1つずれていた（聴力右1000Hz が視力備考扱いになっていた）。修正済み
- **受付NO は 1〜48 の連番**。以前の想定「40〜61」は誤り
- **診察(44)・胸部レントゲン(45)・心電図(46) の列がある**。この48人は全員 `1`。
  SHOKENCD として 017101A(SHIN) / 077010A(ZK020) / 067112A(ZK011) に割当てた。
  **「1」がそれぞれの所見リストで何と表示されるかはプレビューで未確認**
- **視力種別は 1=裸眼 / 2・3=矯正 で確定 (2026/08/08)**。値の分布からは判別できなかったが、
  旧自動入力ツール `kensin_navi_input_v2.py`（pyautoguiで画面に打ち込む方式・実運用実績あり）に
  「種別が1=裸眼ならここに入力、2or3=矯正なら矯正欄へ」と明記されていた。vision_map.csv と一致
- ファイル名が 0615_0617 で2日分が1ファイルに見えたが、**実運用は1日1ファイルにする**と
  業務側が決めた(2026/08/02)。もし2日分が混ざったファイルが来たら、
  受付番号欄で範囲を分けて2回取り込む
- **受診日はA列に入れる運用を推奨 (2026/08/02)**。芝浦は氏名が無く、GUIの受診日を
  打ち間違えると氏名照合が効かないまま別の日の同番号の人に書き込まれ得るため。
  `mapping_shibaura_ai2.csv`(47列・A1=受診日)を追加し、`Detect-MappingPath` は
  HEADERキーワードが多い対応表を優先するようにした(受診日,受付NO,Q1 の3語 > 受付NO,Q1 の2語)。
  日付を入れ忘れた素の46列も従来どおりGUIの受診日欄で取り込める。
  日付は**全員の行に**入れること(空の行はエラーで止まる。安全側)

### 枠が足りない人を健診ナビで直すとき（2026/10/13 石屋 4742・4795 で判明）

- 枠は予約時に「事業所 × コース」の契約項目から作られる。同じコース名でも事業所が違うと枠の数が違う。

- 「検査追加/取消（個別）」の一覧には **セット項目の中身は出ない**。中身のコードで探しても見つからないので、
  【 】付きの親を追加する。

  | 欲しい枠 | 画面で追加するもの | できる枠 |
  |---|---|---|
  | 血糖 068682 | 【血糖】 068681 | 001282 食後時間 + 068682 血糖(未判別) |
  | 裸眼視力 067012/067013 | 【遠方視力】 067010 | 067012 / 067013 / 067018 / 067019 |

- 枠を足したあとは、受付番号欄にその人の番号だけ入れて 3 プレビュー → 4 書込。他の人をやり直す必要はない

## 7. 実装上の落とし穴（すべて実機で踏んだもの）

### Excel COM は使わない
OneDrive上・外部ドライブ上のxlsxを `Workbooks.Open` すると、保護ビュー等のダイアログが**非表示のまま出て永久に固まる**。
→ xlsxはZIP+XMLなので `xlsx_read.ps1` で直接読む。Excelを使うのは「予約取込Excelの書き出し」と「パスワード解除」だけ。

### xlsx読み取りの注意
- `XmlDocument` も `XmlNamespaceManager` も IEnumerable なので、関数から返すときに `,` を付けないとPowerShellが展開してしまう
- 共有文字列は `m:t | m:r/m:t` だけを連結する。`m:rPh/m:t` は**ふりがな**なので混ぜると「健保外」が「健保外ケンポガイ」になる
- シートの `dimension` は104万行などデタラメなことがある。実際に `<row>` がある分だけ読む

### Excelへの書き込み
セルを1つずつ `Cells.Item(r,c).Value2 = 文字列` で埋めると `指定されたキャストは有効ではありません`（InvalidCastException）。
→ `object[,]` を作って `Range.Value2` に一括代入する。速度も桁違い。

### 予約取込フォーマット
- テンプレートによって**見出し行の位置（1行目/2行目）と列構成が違う**（年齢・社員番号・所属名の有無）。列番号を決め打ちにせず、見出しの文字から列を探すこと
- **事業所コードが必須**。空だと事業所が特定できず、連鎖でコースも解決できずコース欄が「形式不正」の赤になる
- 生年月日・予約日は文字列（`2026/07/05`）でよい

### 日付
- `M/d/yyyy` 形式のPCでCSV経由にすると月日が入れ替わる危険。xlsx直読みなら数値のまま読めるので安全
- `260705` `20260705` `2026/07/05` すべて受け付ける
- ファイルに日付列があっても、GUIの受診日欄に入力があればそちらを優先し、確認ダイアログを出す

### IfEmpty / ReqCol / ReqVal (「検査したが所見が空」→ 既定値)
- `IfEmpty` = 入れる結果CD、`ReqCol` = 実施を示す列、`ReqVal` = その列がこの値のときだけ実施とみなす
- `ReqVal` は `|` 区切りで複数可（CSVなのでカンマは使えない）
- `ReqVal` が空だと「ReqCol が空でなければ実施」になる。**書ける列は必ず書くこと**
  未実施を示すコードが入る列だと、未実施を「異常なし」にしてしまう
- 既定値で入れた行はプレビューに `OK(既定値)` と出て、件数も集計に出る

### 安全策（実装済み）
- 書込前に `T_MULTI` を見て、結果入力画面が開いていたら中止
- **`sp_getapplock`**（トランザクション単位）。`T_MULTI` は健診ナビ画面のロックしか見ないので、
  ツールの二重起動・別PCからの同時実行はこれで止める。ロック取得後にもう一度 `T_MULTI` を確認する
- 書込前のデータを `backup\` にCSV保存 → `restore_backup.ps1` で戻せる
- トランザクション。影響行数が1でなければロールバック
- **氏名照合**。Excelの氏名と健診ナビの氏名（カナ優先）が違う人はスキップ。受付番号がずれていると別人を上書きしてしまうため
  正規化は .NET の `FormKC` + ひらがな→カタカナ。`Microsoft.VisualBasic` には依存しない（環境により黙って無効化されるため）
- **プレビューと書込の同一性**。ファイル・更新日時・サイズ・受付番号・受診日・名簿・レイアウト・
  各チェックから指紋を作り、プレビュー時と違えば警告する
- **非常口**（`-Force` / `-IgnoreName`）は使用時に内容を列挙して再確認し、書込のたびにチェックを自動で外す
- **受付済み（`T_KANJA_G` に行がある）の人は受付番号を変更しない**。健診ナビ側が別に番号を持つため
- 名簿でしぼり込み（`-Roster`）。血液など名簿外が混ざるファイル用。照合はPK_SEQで行う

### あえて採用しなかったこと
- 「本番DB（`K166_SIBAURAUSER`）では `-IgnoreName` を禁止」
  → このクリニックにはテスト用DBが無く、**本番DBでテストしている**（テスト用受診者を本番に作る）。
    禁止するとテストができなくなるため、代わりに「毎回リセット＋明示確認」にした

### 配布ZIP
UTF-8フラグ付きZIPだとWindowsのエクスプローラーで日本語ファイル名が化ける。
→ `make_zip.py` がファイル名をcp932で書き、UTF-8フラグを立てない。

事前に決めた基準（枠がある人数＝所見が入っている人数なら全員撮っている）を満たしたので、

撮らない人が出るようになったら `ReqCol=105` `ReqVal=1` を足せば、
「判定欄に1を書いた人だけ補完」の安全側に戻せる（下記の経緯を参照）。

<details><summary>そこに至るまでの経緯 (2026/07/31)</summary>

リアンの **44列 心電図検査№ は受付番号のコピー**（42列の胸部X線フィルム№も同じ）。

「枠はあるが撮らない人がいるかもしれない」と業務側から回答があったため、
44列を実施印にする案は破棄。代わりに業務側から
「異常のない人には異常なしの1を入れればいいか」と提案があったので、
**`mapping_rian.csv` 101列を `IfEmpty=1` / `ReqCol=105` / `ReqVal=1` にした**。

- 所見(101列)に値がある → そのまま入る（従来どおり）
- 所見が空 かつ 判定(105列)が `1` → 正常範囲(ZK011の結果CD 1)を入れる
- 所見が空 かつ 判定が空/2/3/4 → **何も入れない**

判定欄に1を入れる運用が始まっていなくても副作用は無い（該当者0人になるだけ）。
所見欄に直接 `1` と書いた場合も、SHOKENCD の通常経路で正常範囲になる。

心電計のCSV（`心電図取込.bat`）から入れる方法も従来どおり使える。
このCSVには実際に測定した人しか出てこないので、実施の有無で迷わない。

全員必ず撮ると確認できたら `ReqCol` / `ReqVal` を外せば全員に既定値が入る。
`check7.bat` で過去の実績（枠がある人数 vs 所見が入っている人数）を確認できる。

95列 撮影区(全員 `1`) と 50列 診察判定(`1`/`3`) は `ReqVal` で値を限定済み。
未実施を示すコードが来ても既定値は入らない。
