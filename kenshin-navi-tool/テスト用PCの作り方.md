# テスト用PC（サーバーに繋がない1台）の作り方

本番のデータを触らずに、取込や請求の試験をするための環境です。
ネットワークから切り離した1台のPCの中だけで健診ナビを動かします。

---

## 先に決めておくこと（2つ）

### 1. メーカー（健診ナビの販売元）に一言入れる

健診ナビは購入したソフトです。**2台目に入れてよいかはライセンス次第**なので、
先に「試験用に1台、サーバーに繋がない形で入れたい」と伝えて確認してください。

たいていの業務ソフトは検証用の導入を認めています。断られた場合でも、
**ツール側（excel_tools）の試験だけならDBのコピーだけで足ります**（健診ナビの画面は使えませんが、
取込・請求の計算は全部試せます）。

### 2. 患者さんのデータをコピーすることになる

本番DBをそのままコピーすると、**全受診者の氏名・生年月日・検査結果がそのPCに入ります。**
持ち出し扱いになるので、少なくとも次を守ってください。

- そのPCは院内に置く。持ち出さない
- BitLocker などでディスクを暗号化する
- Windowsにパスワードをかける
- 試験が終わったら消す

**氏名を仮名に置き換えた版を作ることもできます**（担当者に相談してください）。
その場合は持ち出しの心配がかなり減ります。

---

## 手順

### ① テストPCに SQL Server Express を入れる

無償です。Microsoftのサイトから「SQL Server Express」をダウンロードして入れます。

- **本番と同じか、新しいバージョン**を選ぶこと（古いと復元できません）
- インスタンス名は本番と同じ **`SQLEXPRESS`** にしておくと設定が楽です
- 認証は「混合モード」を選び、`sa` のパスワードを決めておく
- 一緒に **SQL Server Management Studio (SSMS)** も入れる（復元作業に使います）

`check13.bat` の結果に本番の版とバージョンが出ます。

### ② 本番DBのバックアップを取る

`check13.bat` の「最後のフルバックアップ」に日付が出ていれば、その `.bak` を使えます。
無ければ、SSMSで `K166_SIBAURAUSER` を右クリック →「タスク」→「バックアップ」で作ります。

**バックアップを取るだけなら本番に影響しません**（動いたまま取れます）。

### ③ テストPCで復元する

SSMSで「データベース」を右クリック →「データベースの復元」→ 手順②の `.bak` を指定。
DB名は本番と同じ **`K166_SIBAURAUSER`** にします。

※ SQL Server Express は **1つのDBが10GBまで**という制限があります。
`check13.bat` の「データMB」が10,000MBを超えていたら Express では入りません。
その場合は Developer Edition（無償・検証用途に限り使用可）を使います。

### ④ 健診ナビのクライアントを入れる

- 本番PCの **`\\KNSV\KenshinNavi`** フォルダを、テストPCのローカル（例 `C:\KenshinNavi`）に丸ごとコピー
- 健診ナビ本体のインストールはメーカーの手順に従う
- **`SQLSV\SQLServerConnect.txt` の接続先を、そのPC自身（`localhost\SQLEXPRESS` など）に書き換える**

これでサーバーを見に行かなくなります。

### ⑤ excel_tools をテストPCで使う

`excel_tools` フォルダをコピーして、そのまま使えます。
接続先は健診ナビと同じ `SQLServerConnect.txt` を読むので、**④で書き換えれば自動的にテストDBを向きます。**

別の場所を見せたいときは、`start.bat` を右クリック→編集して次のように書けます。

```
powershell -NoProfile -ExecutionPolicy Bypass -File "%~dp0form_import_gui.ps1" ^
  -ConnectionString "Data Source=localhost\SQLEXPRESS;Initial Catalog=K166_SIBAURAUSER;Integrated Security=True"
```

---

## 取り違え防止（これは必ずやってください）

テストPCと本番PCを間違えるのが一番こわい事故です。

- **テストPCの壁紙を派手な色にして「テスト機」と大きく書く**
- テストPCの `excel_tools` フォルダ名を `excel_tools_TEST` にする
- 本番PCでは絶対にテスト用の接続文字列を使わない

`form_import` は書込前に必ず接続先を画面に出します（`[DB] 接続先: ...`）。
**書込実行の前に、そこが `localhost` になっているか目で確かめる**習慣にしてください。

---

## この環境でできること

- 取込のプレビュー・書込実行の練習
- 請求一覧・費用明細書の試算
- 対応表（mapping / 料金表 / ルール）を変えたときの動作確認
- 「元に戻す」の練習
- 新しいレイアウトのExcelが来たときの下調べ

**本番に一切影響しません。**壊しても復元し直せば元通りです。

---

## できないこと

- 検査機器（心電計など）との連携
- 東振協などへのオンライン提出
- 本番の最新データの反映（コピーした時点のデータのままです）

新しいデータで試したくなったら、②③をやり直して入れ替えます。

## 自分のPCで開発する場合（おすすめ）

事務員PCで作業すると業務を止めてしまいます。**自分のPCにコピーを作って、そこで開発するのが正解です。**

ただし自分のPCに患者データを置くのは避けたいので、**復元したあとに氏名などを架空の値に置き換えます。**

### 手順

1. `C:\HIT\K166_SIBAURAUSER.bak` をUSBで自分のPCへコピー
2. SQL Server Express に復元（DB名は `K166_SIBAURAUSER` のまま）
3. **`mask_testdb.ps1` を実行して仮名化する** ← ここが大事

```
rem まず何が置き換わるか見る (書き換えません)
powershell -ExecutionPolicy Bypass -File mask_testdb.ps1 ^
  -ConnectionString "Data Source=localhost\SQLEXPRESS;Initial Catalog=K166_SIBAURAUSER;Integrated Security=True"

rem 実際に置き換える
powershell -ExecutionPolicy Bypass -File mask_testdb.ps1 ^
  -ConnectionString "Data Source=localhost\SQLEXPRESS;Initial Catalog=K166_SIBAURAUSER;Integrated Security=True" -Commit
```

4. 仮名化が終わってから、USBの `.bak` を消す

### 何が置き換わるか

| 置き換える | そのまま残す |
|---|---|
| 氏名（「検査0001太郎」の形になります） | 検査結果・判定 |
| 生年月日（年はそのまま、月日は1/1に） | コース・料金・事業所名 |
| 住所・電話・メール・保険証番号 | 受診日・受付番号 |
| 社員番号・カルテNo | 検査枠の構成 |
| 変更履歴ログ（氏名が残るため削除） | |

**取込・請求・帳票の試験はそのままできます。**個人が特定できる情報だけが消えます。

### 安全装置

`mask_testdb.ps1` は**サーバー名に `KNSV` が含まれていたら実行を拒否します。**
本番で誤って走ることはありません。さらに実行時にはサーバー名の入力を求めます。

### 注意

- 仮名化すると、**リアンの実ファイルとの氏名照合テストはできなくなります**（名前が変わるため）。
  照合の試験だけは、クリニック内のテストPC（仮名化しない版）で行ってください
- 仮名化しても**受診データそのもの**は残ります。念のため自分のPCも暗号化しておいてください
