## 1. 福生の予定者データの形

名簿（振り分け表 Excel、2026-10-01 版 325 人）をアプリに読み込み、1 人ずつ次の形で持っている。

| 項目 | 中身 | メモ |
|---|---|---|
| `id` | 元名簿の受診者ID（`P0001` など） | アプリの中で 1 人を指す番号 |
| `planned.company` | 事業所名 | 振り分け表の書き方（健診ナビの団体名とは違う） → `form/fussa_company_map.csv` で健診ナビの団体CD に読み替えている |
| `planned.name` | 漢字氏名 | Excel のふりがな（rPh）が混ざらないよう頼んだ経緯あり |
| `planned.kana` | カナ | 福生の名簿には無かった。当日入力を頼んだ |
| `planned.gender` / `planned.birth_date` | 性別・生年月日 | |
| `planned.date` | 予定日 | |
| `planned.time` / `planned.order` | 時間帯（例 10:00～10:15）・順番 | |
| `planned.course` | コース A / B / C | 健診ナビでは FA / FB / FC |
| `planned.options` | オプションの記号の配列（D・M など） | 3 を参照 |
| `planned.cancelled` | 取消 | |
| `actual.*` | 当日の受付結果（来た・受付番号・当日コース・当日オプション・便本数・採血/胃/尿の変更・受付時刻） | |
| `derived.*` | アプリが計算した判定（受付済み・取消・コース変更・オプションの追加/中止・受診日の変更） | |

ファイル全体には `series_id`（`fussa_2026`）・`exported_at`・`revision` があり、古いファイルの取り込み防止に使っている。

## 2. 既存の照合方法（福生）

`受付結果取込.ps1` は次のやり方で、アプリの人と健診ナビの予約を突き合わせている。

1. 対象: アプリの予定日・実際の受付日に受診する、団体名に「福生」が入る人（＋事業所対応表の団体）
2. **漢字氏名（空白を詰めたもの）が 1 件だけ一致**した予約を、その人とみなす（325 人で同姓同名 0 件だったので成り立った）
3. 一致しない・2 件以上 → 書かずに一覧に出す
4. 一度当たった人は「受診者ID ↔ 健診ナビの PK_SEQ ↔ 個人ID」の対応表を `backup\対応表_<series_id>.csv` に残す

**新島ではこの氏名照合を使わない。** 健診ナビから事前登録するので、最初から予約ID（PK_SEQ）を持たせられる。

## 3. 新島での番号の分け方

| 番号 | 中身 | どこで決まるか | 使い道 |
|---|---|---|---|
| 受診者番号 | 新島の受付アプリでの番号（例 `N0001`） | 事前登録のときに付ける | 受付・名簿で普段使う番号 |
| 予約ID | 健診ナビの `T_KENSIN.PK_SEQ` | 健診ナビ | **予約 1 件の識別子。** 受付番号を戻すときの当て先。画面には出さなくてよい |
| 個人ID | 健診ナビの `T_KOJIN1.KOJIN_ID` | 健診ナビ | 人の識別子（年をまたいでも同じ）。前回値などに使う |
| 受付番号 | 当日の番号 | 当日の受付 | 検体依頼に使う。健診ナビの `T_KENSIN.UKE_NO_KENSA` に戻す |

見本（`新島_事前登録_見本.csv` / `.json`）はこの分け方にしてあります。

## 6. 受付番号を健診ナビへ戻す方法と注意点（今は実行しない）

福生で使っている `受付結果取込.ps1` の考え方を、予約ID で当てる形にする。

1. 受付アプリの出力から、受付済みの人の「予約ID・受付番号・受付した日」を読む
2. 健診ナビでその予約ID の予約を読み、**取消になっていない・個人ID と氏名が事前登録のときと同じ**ことを確かめる
3. **予約の受診日と受付した日が同じときだけ**書く（別の日の予約に書くと、日付で切る検体依頼から抜ける・番号が重なる）。違う人は一覧に出して人が判断
4. すでに別の受付番号が入っている予約には書かない（一覧に出す）
5. 受付番号の列の桁（numeric の大きさ）を超えないか、同じ日に同じ番号が無いかを確かめる
6. 全部プレビュー → Y で書く。書く前に控え、1 つのトランザクション、applock、書いたあと読み直し
7. 取消・受診日の変更・コース変更・オプション変更は書かない（一覧に出すだけ）

## 7. ダミーでの取り込み検証の段取り

アプリの元ファイルが手に入ったら、次の順で進める（実在の名簿・健診ナビへの書き込みは使わない）。

1. 福生のアプリをコピーして**新島用の別フォルダ**を作る（福生のフォルダ・データベースには触らない）
2. データベースのファイル名・`series_id`（`niijima_2026`）・ポートを新島用に変え、**別のデータベース**で動かす
3. ダミーの名簿（見本の 3 人）を読み込ませ、受付・当日オプション追加・取消・受診日変更を一通りやる
4. アプリが出す JSON を、健診ナビにつながない検証用の読み取りで確かめる（予約ID・受付番号・オプションが正しく出るか）
