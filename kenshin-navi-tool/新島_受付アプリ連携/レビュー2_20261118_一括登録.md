### 3.2 1 予約分の書込み（骨組み。未実行）

```powershell
function Write-OptionPlanForReservation($conn, $ctx, $previewFingerprint) {
  # $ctx: Reservation(PK_SEQ) / Individual(KOJIN_ID) / Day('yyyy/MM/dd') / Company / Course / Number / Codes(昇順)
  $tx = $conn.BeginTransaction([Data.IsolationLevel]::ReadCommitted)
  try {
    Invoke-Execute $conn $tx 'SET LOCK_TIMEOUT 5000' @{}          # 健診ナビを待たせない。取れなければこの人は飛ばす
    # (1) 予約の行を鍵にする。この行を UPDLOCK+HOLDLOCK で持っている間、同じ予約を別のツールは触れない
    $k = Invoke-Query $conn $tx @'
SELECT PK_SEQ, KOJIN_ID, D_KENSIN, F_TORIKESI, F_IRAI, DANTAI_CD1, COURSE_CD, UKE_NO_KENSA, SEQ1, SEQ2
FROM T_KENSIN WITH (UPDLOCK, HOLDLOCK, ROWLOCK) WHERE PK_SEQ = @pk
'@ @{ pk = [decimal]$ctx.Reservation }
    if ($k.Rows.Count -ne 1) { throw 'skip:reservation_missing' }
    $r = $k.Rows[0]
    if ([string]$r.D_KENSIN -cne $ctx.Day -or [string]$r.KOJIN_ID -cne $ctx.Individual -or [string]$r.F_TORIKESI -cne '0' -or
        [string]$r.DANTAI_CD1 -cne $ctx.Company -or [string]$r.COURSE_CD -cne $ctx.Course) { throw 'skip:reservation_changed' }
    if ([string]$r.F_IRAI -ceq '1') { throw 'skip:specimen_request_already_created' }
    if ($r.UKE_NO_KENSA -is [DBNull] -or [decimal]$r.UKE_NO_KENSA -ne [decimal]$ctx.Number) { throw 'skip:reception_number_not_imported_or_different' }
    # (2) 健診ナビの結果入力画面で開かれている人は飛ばす (T_MULTI。form_import.ps1 の Test-Locked と同じ見方)
    if (Test-Locked $conn $ctx.Reservation $tx) { throw 'skip:open_in_kenshin_navi' }
    # (3) その予約の検査・料金を全部、鍵を掛けて読み直す
    $tests = Invoke-Query $conn $tx 'SELECT * FROM T_KENSA  WITH (UPDLOCK, HOLDLOCK) WHERE PK_SEQ = @pk' @{ pk = [decimal]$ctx.Reservation }
    $fees  = Invoke-Query $conn $tx 'SELECT * FROM T_RYOUKIN WITH (UPDLOCK, HOLDLOCK) WHERE PK_SEQ = @pk' @{ pk = [decimal]$ctx.Reservation }
    $master = Read-OptionMasters $conn $tx $ctx.Company $ctx.Course $ctx.Codes      # T_SET2 / T_KOMOKU / M_OPTION (読むだけ)
    # (4) 計画を作り直し、プレビューのときと 1 文字も違わないことを確かめる
    $plan = New-ReservationOptionPlan $ctx $tests.Rows $fees.Rows $master            # 複数オプションを順に積む
    if ((Get-PlanFingerprint $plan) -cne $previewFingerprint) { throw 'skip:changed_after_preview' }
    if (-not $plan.TestInserts.Count -and -not $plan.FeeInserts.Count) { $tx.Rollback(); return 'already_present' }
    # (5) 書く前の控え (この予約の検査・料金の全行) と、元に戻す SQL
    Save-OptionBackup $ctx $tests.Rows $fees.Rows $plan
    # (6) 書く。列は名前を全部書き、型を明示した引数で渡す。NULL は DBNull、空文字は '' のまま
    foreach ($t in $plan.TestInserts) { if ((Invoke-InsertTest $conn $tx $t) -ne 1) { throw 'rollback:test_insert' } }
    foreach ($f in $plan.FeeInserts)  { if ((Invoke-InsertFee  $conn $tx $f) -ne 1) { throw 'rollback:fee_insert' } }
    # 連番 99 は「読んだときの値のままなら」書き換える (列ごとに元の値を条件に入れる)
    if ((Invoke-UpdateTotal $conn $tx $plan.TotalBefore $plan.TotalAfter) -ne 1) { throw 'rollback:total_changed' }
    # (7) 全行を読み戻し、「書く前の全行 ＋ 計画した行 (連番 99 は差し替え)」と全列で一致することを確かめる
    $t2 = Invoke-Query $conn $tx 'SELECT * FROM T_KENSA  WHERE PK_SEQ = @pk' @{ pk = [decimal]$ctx.Reservation }
    $f2 = Invoke-Query $conn $tx 'SELECT * FROM T_RYOUKIN WHERE PK_SEQ = @pk' @{ pk = [decimal]$ctx.Reservation }
    if ((Get-OptionFingerprint $t2.Rows $script:OptionTestColumns @('KOMOKU_CD')) -cne $plan.ExpectedTestsFingerprint -or
        (Get-OptionFingerprint $f2.Rows $script:OptionFeeColumns  @('REN'))       -cne $plan.ExpectedFeesFingerprint) { throw 'rollback:readback_mismatch' }
    $tx.Commit(); return 'written'
  } catch { try { $tx.Rollback() } catch {}; throw } finally { $tx.Dispose() }
}
```

- 外側で、ツール全体の二重起動を止める鍵（セッションの applock `NIIJIMA_OPTION:niijima_2026`）を 1 つ取る。予約ごとの排他は (1) の行の鍵で足りる。
- `skip:` は「この人を飛ばして次へ」、`rollback:` は「この人を戻して次へ（一覧に出す）」。`rollback:` が 1 件でも出たら、残りを続けるかは止めて人に聞く方が安全（作りの誤りの可能性があるため）。
- 型の明示（`AddWithValue` を使わない）:

| `SEQ1`・`SEQ2` | `VarChar(12)` |
| `KOMOKU_CD`・`OYA_KOMOKU_CD` | `VarChar(10)` |
| `KEKKA` | `NVarChar(225)`（値は空文字） |

### 3.4 冪等・再実行・元に戻す

- **もう一度流す**: その予約に「親＋子全部＋料金 1 行」が揃っていれば `AlreadyPresent` で何もしない。一部だけある・別の親の下にある → 止める（今の作りのまま）。
- **途中で止まった**: 1 予約単位で確定しているので、同じ JSON を流し直せば残りだけ進む。
- **元に戻す SQL**（1 回の実行で 1 ファイル。予約ごとに 1 かたまり）: 「まだ誰も触っていない行だけ」を消す。

```sql
-- 例 (1 予約分)。条件に合わなければ何も消さずに止まる
SET XACT_ABORT ON; BEGIN TRANSACTION;
DELETE FROM T_KENSA WHERE PK_SEQ = 2008025 AND KOMOKU_CD IN ('OP0001','067818','068690')
```

## 4. ほかのオプションへ広げられる範囲

マスタ（`T_SET2`・`T_KOMOKU`）と過去の実物（DB 確認 1。付けた予約の半分以上にある行）を並べた。

| オプション | マスタの中身 | 過去の実物（親の下にあった行） | 見立て |
|---|---|---|---|
| OP0002 | `067818` | `067818`（9/9） | OP0001 と同じ形。**広げてよい見込み** |
| OP0003 | `068690` | `068690`（17/22。残りは別の親の下＝重なり） | 同上 |
| OP0004 | `067812`・`067823` | 2 つとも 35/35 | 同上 |
| OP0005 | `067802`・`067804`・`067809` | 3 つとも 49/49 | 同上 |
| OP0006 | `067841`＋**`067842`〜`067845`**（さらに `067841` の中身としても同じ 4 つ） | `067841` だけ（26/26）。`067842`〜`067845` は半分未満 | **マスタと実物が違う。決められない** |
| OP0007 | `068205`・`068206`・**`068211`・`168611`**（`168611` の中身は `068660`〜`068662`） | `068205`・`068206`（13/13）。`068211`・`168611` は半分未満 | 同上 |
| OP0008 | **`068360`**＋`068361`〜`068399` | `068361`〜`068399`（20/20）。`068360` は 11/20 | 同上（`068360` は途中からマスタに入った形） |
| OP0009 | `069245`・`069246` | 親＋`069246`（58/60）。`069245` は親なし・F_KOMOKU 0 で 33/60 | **基本コースに 1 回目がある人は 2 回目だけ足す**動きに見える。場合分けが要る |

- OP0002〜OP0005 は、中身が全部「セットでない検査（K_SET 0）・初期値なし」で、OP0001 と条件が同じ。**画面の追加処理が検査ごとに別の作りになっているとは考えにくいが、NULL と空文字まで同じかは実物で 1 回見れば確定する**（5 章で 1 クリックずつ）。見ないまま本番に使うことは勧めない。
- OP0006・OP0007・OP0008 の食い違いは、**マスタが途中で書き換えられた**（過去の予約は当時のマスタで作られた）と読むのが自然だが、証拠からは「いまの画面が何行作るか」を決められない。集計が半分以上の行しか出していないので、少数派の形（たとえば最近の予約だけ `067842`〜`067845` がある）も隠れている。**いまの画面で 1 回付けた実物が唯一の根拠**（5 章）。
- OP0009 は、`069245` が基本コースにある人とない人で 2 通り。どちらの実物も要る。会期の予約のうち何人が基本コースに `069245` を持つかを先に数える（読むだけ）。
- **HbA1c**: セット `OPI024`（中身 `068689`）はあるが、団体 0000000003・コース B/C の定義（`M_OPTION`）に無い → 料金が決まらないので料金の行を作れない。先に次の 2 つを数える（読むだけ）。基本コースにもう入っているなら、追加そのものが要らない。

```sql
-- 会期の予約で、基本の検査に HbA1c (068689) がもう入っている予約の数 (コースごと)
SELECT s.COURSE_CD, COUNT(*) AS 予約数, SUM(CASE WHEN EXISTS (SELECT 1 FROM T_KENSA k WHERE k.PK_SEQ = s.PK_SEQ AND k.KOMOKU_CD = '068689') THEN 1 ELSE 0 END) AS HbA1cあり
FROM T_KENSIN s WHERE s.D_KENSIN BETWEEN '2026/11/22' AND '2026/11/24' AND s.F_TORIKESI = 0 GROUP BY s.COURSE_CD;
-- 過去に HbA1c をあとから足した予約が、どのコード・どの料金で入っているか (件数だけ)
SELECT r.KOMOKU_CD, r.F_ADD_DEL, r.GOUKEI, COUNT(*) AS 行数 FROM T_RYOUKIN r
WHERE r.KOMOKU_CD IN ('OPI024','068689') GROUP BY r.KOMOKU_CD, r.F_ADD_DEL, r.GOUKEI;
```

  それでも足す必要があり、料金を健診ナビに持たせるなら、**団体のオプション定義に HbA1c を登録するのは健診ナビの画面での作業**（マスタなのでツールでは触らない）。決まるまでは「手入力の一覧」に出す今の扱いでよい。

## 5. 残りの実機確認 — 1 回のリハーサルにまとめる

**使うのは架空の 2 名だけ。会期の予約・マスタ・`F_IRAI` には触らない。**

### 準備（利用者・健診ナビの画面）

- 架空 2 名に、**会期でない日（例 11/19）の新しい予約**を 1 件ずつ作る。団体・コースは 2 名とも同じ（コース B）。まだ検体依頼を出していないこと。
  - **S** = 画面で付ける方、**T** = ツールで付ける方。
- S にだけ受付番号を入れる（T はまだ入れない）。

### 手順

| # | だれが | やること | 分かること |
|---|---|---|---|
| R1 | 読むだけ | S・T のスナップショット ①（`PK_SEQ` を持つ全表の行数と指紋、`T_KENSIN` の行、`T_KENSA`・`T_RYOUKIN` の全行） | 出発点。S と T が同じこと |

## 7. 判断が要ること（利用者）

1. **料金の行を健診ナビに作るか。** 請求書を受付アプリから出すなら、健診ナビの料金の行は「画面で付けたときと同じ状態にしておく」ためだけのもの。作らないと、あとで画面を開いた人が見る料金と実施予定が食い違う。**作る（画面と同じにする）方を勧める。**
2. **HbA1c をどう扱うか**（4 章の数を見てから）。
3. **R6 が一致しなかった／間に合わなかった場合、会期は画面での手入力で進める**ことでよいか。
4. 来なかった日の予約（3 日分のうち使わなかった方）を、会期後に健診ナビで取り消すこと。対象の一覧は読むだけで作れる。
